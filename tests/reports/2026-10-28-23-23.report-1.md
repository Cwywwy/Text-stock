- 命令：`.venv\Scripts\python.exe -m pytest tests -q`
- 结果：**330 passed / 0 failed**（耗时 11.35s）
- 基线：`main` 末次 **324 passed**，本分支新增 6 项（`tests/test_snapshot.py` +6）

## 背景（为什么要改）

用户反馈：云端页面「期望最新交易日 2026-10-27」已更新，但「行情最新交易日」停在 2026-09-03；
点「☁️ 从云端快照恢复数据」后仍然没有变化（体检仍是 5553 只、2026-09-03）。

根因（两处叠加）：

1. `update_center._restore_from_snapshot()` 直接调用 `raw_base_url()`，读的是孤儿分支
   `data-snapshot`。该分支最后一次提交是 2026-09-04，`manifest.created_at = 2026-09-04 02:50:51`、
   `bars_count = 5553` —— 与页面上的 5553 只 / 2026-09-03 完全吻合。而 2026-10-15 起发布端已改到
   GitHub Releases（`DEFAULT_BACKEND = "release"`），手动恢复没有跟着改，等于每次"恢复成功"都把
   云端数据退回 9 月。
2. `bootstrap_if_needed()` 只要本地 `bars >= MIN_BARS_READY(100)` 就 return，云端已有 5553 个旧文件，
   因此冷启动永远不会再从 Release 恢复 —— 唯一入口就是那个用错地址的按钮。

## 数据缩减说明

不涉及大数据测算。快照下载路径的测试全部用 `monkeypatch` 替换 `restore_from_url` / `restore_with_fallback`，
不发真实网络请求、不下载 300MB 分卷；断言的是**地址与参数装配**（本次事故的根因层），
真实下载与 sha256 校验逻辑由既有用例与 `scripts/acceptance.py --full` 的快照往返覆盖。

## 过程中发现的环境问题（与业务无关）

本机 DSH 沙箱的写入权限项（`S-1-4-*` capability）没有从 `D:\DeepSeekHarness` 继承到旧的
`D:\DeepSeekHarness\案例区` 目录，导致 `git`、`pytest` 等子进程写文件被拒（`访问被拒绝`），
而 `write`/`edit` 工具不受影响。已对该目录补一条与根目录一致的允许写入项（原权限 SDDL 已备份、
可用 `icacls` 反向删除恢复），补齐后 `git checkout -b`、`pytest` 写报告恢复正常。
