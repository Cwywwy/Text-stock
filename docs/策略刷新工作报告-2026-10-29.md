# 第一部分：大白话版

## 1. 这个系统在干什么（先统一语境）

这个项目是"A 股盘前选股系统"：每天开盘前，用历史日线（开盘/最高/最低/收盘/成交量/成交额/换手率）+ 少量财务数据，给全市场 5000 多只股票打分，选出前几名，并给出买入价、止盈止损。策略目前有 7 个内置的（趋势跟随、动量、均值回归、突破、价值、段永平、李录）。

之前你已经做完了一轮"选型调研"：从 40 个候选因子里挑出三个最值得试的（收敛因子、动量方向修正、RRG 行业轮动），并决定这一轮照做，同时补做「两段式 LLM 配置」和两个数据字段。

**但调研只回答了"值不值得试"，没回答"试了到底行不行"。** 我这次的工作，本质是：**建一条可复现的试验流水线，把"值不值得"变成"过没过线"的数字。**

## 2. 顺序为什么是这样

调研里给的顺序是 ①收敛因子 → ②动量修正 → ③RRG 轮动，我基本照做，但在最前面插了一步"基线固化"：

1. **先量基线**（Phase 6）：同一批股票、同一区间、同一套参数，把 7 个策略现在的成绩单先打出来。没有这张成绩单，后面任何"改进了没有"都是空话。
2. **再做 A 收敛因子**（Phase 7）：改动小（一个 rolling.std），先验证"加一个维度有没有用"。
3. **再做 B 动量方向修正**（Phase 8）：改两行代码的事，但赌的是"研报说 A 股裸涨幅动量 IC 全负"这条结论在我们数据上成不成立。
4. **再做 C RRG**（Phase 9）：工作量最大（2–3 天），但调研已写清"如果行业层都没有超额，就停"，所以它是"成本最低的证伪路径"。
5. **D 两段式**（Phase 11）：纯产品能力，和因子对错无关，放在证据类工作之后做，避免"功能做完了才发现方向错了"。
6. **E 字段补齐**（Phase 12）：补数据是长期基础设施，越早越好，但它不影响已有策略，所以放最后。
7. **终验 + 收尾**（Phase 13）：把所有东西合起来复核一遍，写文档、归档。

每一阶段我都设了一个"检查点"（G2–G6）：拿到数字先停下问你，你点头才进下一阶段。这样不会出现"你埋头改了三天，方向错了"的情况。

## 3. 三个"没通过"到底是什么意思

用 B 动量修正举例：研报说 A 股用"过去 20 天涨幅"选股是反的，应该用"均线/价格"（离均线越近越强）。我照做了，然后同区间对比：

| 口径 | 总收益 | 年化 | 最大回撤 |
|---|---:|---:|---:|
| 原口径（20 日涨幅，正在用的） | −32.91% | −9.15% | −41.16% |
| 研报口径（MA/close） | −53.26% | −16.71% | −55.88% |
| 混合口径（四条均线百分位平均） | −45.99% | −13.77% | −51.79% |

**结论：改完更差，而且差很多。** 所以按你事先定好的规则——"如果改完变差，就保留原样并在报告说明"——我把新口径做成可选参数、默认还是老口径。这叫"证伪"，不是失败：**我们用一次实验省下了以后几个月在一个错方向上的投入。**

A 和 C 同理：
- A 收敛因子：趋势跟随策略加了它以后，全档都变差（回撤多亏 2.3–2.7 个百分点），突破策略只有一档好一点点、且没有规律 → 默认关闭。
- C RRG：行业轮动 4 年 +37.15%，而"31 个行业等权持有"这个笨办法 +39.73%，**跑输 0.53 个百分点/年**（门槛是至少赢 2 个点）→ 按规则不做第二步（把行业信号落到个股）。

## 4. 那这轮到底得到了什么

不是"什么都没做出来"，而是四类实实在在的东西：

1. **一条可复用的试验流水线**：`scripts/measure_factor_ab.py`，以后任何"加个因子看有没有用"都能半小时内出带分年度、换手率、回撤的报告，不用每次手写脚本。
2. **三个已被证伪的方向**：以后不用再在这三个方向上花时间（这是有价值的"负结果"）。
3. **一套新能力**：六种策略类型的下拉 + LLM 只能在白名单里发挥 + 缺字段的规则会在报告里明确告诉你"今天少算了哪一条"；再加上总股本、逐日流通股本、财报披露日三个数据字段。
4. **一个诚实的问题定位**：真正的问题是换手太高（成本每年吃掉 5.8–7.6 个百分点）和熊市不设防，而仓库里现成的 `regime.py`（市场阶段）和 `market_timing`（择时开关）**至今没有任何策略在用**。

## 5. 过程中踩的坑（真实记录）

- **环境权限**：开始时沙箱不允许我写项目目录，导致测试跑出 114 个"临时目录删不掉"的假报错。把会话切到完全访问后复跑，445 条全过。教训：报错要看"是不是环境问题"，别急着改代码。
- **子进程编码**：中文 Windows 下子进程输出是 GBK，父进程按 UTF-8 解会崩，加 `PYTHONIOENCODING=utf-8` 解决。
- **PowerShell 5.1**：不支持 heredoc；`python -c` 里的花括号会被它当自己的语法解析；`Set-Content -Encoding utf8` 会加 BOM 让 JSON 读不了。后来一律"写临时 .py 文件再执行"。
- **pandas 3.0 的破坏性变化**：`df.stack(dropna=False)` 直接抛 `ValueError`，只能改成无参 `stack()`。
- **数据回补漏了 ST 股**：第一版股本历史少了 197 只 ST 股，因为行情加载默认排除 ST；数据层不该替策略层做取舍，改成 `exclude_st=False` 重跑。
- **网络封禁**：东财接口 https 被重置、后来 http 也被重置，所以给回补脚本加了 `--skip-fetch`，可以复用已落盘的快照离线重算历史。

## 6. 你只需要记住的三句话

1. 加了三个因子方向，全部没过验收线，所以**默认一个都没打开**；系统行为和以前完全一样。
2. 新增的"两段式配置"和"两个数据字段"是真能用的，且都有降级提示。
3. 下一步最值得做的不是"再找因子"，而是"降换手 + 熊市择时"。

## 2.3 逻辑主线（为什么每一步必须在前一步之后）

```
① 固化基线 ──→ ② 造测量工具 ──→ ③ 单因子 A/B（A） ──→ ④ 公式替换 A/B（B）
        │                                                        │
        └──────────────┬─────────────────────────────────────────┘
                       ↓
              ⑤ 预注册判定线（在跑之前写死）
                       ↓
        ┌──────────────┴──────────────┐
        ↓                             ↓
   ⑥ 通过 → 默认打开            ⑦ 不通过 → 默认关闭 + 写报告说明
                                      ↓
                        ⑧ 增量能力（D 两段式 / E 字段）不受结论影响，照做
                                      ↓
                        ⑨ 终验：7 策略逐值对比 + 全量测试 + 文档 + 归档
```

三条硬规则贯穿全程：

1. **可复现优先**：同一配置跑两遍必须逐字符相同（实际抽 3 个 arm 验证过）；否则 A/B 结论没有意义。
2. **默认关闭原则**：任何新能力不得改变既有策略的默认输出。这条最终靠端到端回测逐值对比来证明，而不是靠读代码。
3. **负结果要留档**：不成立的方向写进报告与 CHANGELOG，避免半年后有人再试一遍。

**关键概念**：
- `bars_map` 是 `dict[股票代码] → DataFrame`，每个 DataFrame 是**一只股票的时间序列**。
- 因子行是**横截面**：某一天、每只股票一行，列是当天的因子值（ma20、rsi14、mom_ret……）。打分就是在横截面上比较。
- 引擎里统一用"列字典"构造行，和实盘 `build_factor_rows()` 保持**列名与数值完全一致**——这是 `tests/test_factor_parity.py` 存在的原因：两条代码路径算同一只股票的同一天，必须一模一样，否则回测结论和实盘信号对不上。

### 2.4.2 因子是怎么算出来的（以收敛因子为例）

```python
# 1) 先算多条均线：MA_1 就是价格本身，其余是滚动平均
ma = pd.DataFrame({f"ma{w}": series.rolling(w, min_periods=w).mean()
                   for w in (1, 5, 10, 20, 60, 120)})

# 2) 六条均线之间的"离散程度"：标准差越大 = 均线越散开 = 趋势越不稳定
std = ma.std(axis=1, ddof=1, skipna=False)   # 注意 skipna=False

# 3) 取负对数：std 越小 → 值越大（越"收敛"）
conv = -np.log1p(std)
```

三个新手最容易踩的点：

1. **`min_periods=w`**：120 日均线在只有 60 天数据时不能算，必须给 NaN。否则会拿"半截均线"当完整值用。
2. **`skipna=False`**：如果允许跳过 NaN，那么第 50 天时"1/5/10 日均线有值、20/60/120 是 NaN"，标准差只按前 3 个算，会得到一个偏小的 std——**把"数据不全"误判成"很收敛"**。这是本模块第一条注释就写明的坑。
3. **量纲问题**：`std` 的单位是"元"。贵州茅台均线散开 5 元，和一只 3 元股票散开 5 元，数值一样但含义完全不同。所以：
   - 报告里另给一列 `conv_pcf_cv = -log1p(std / |mean|)`（无量纲，纯诊断）；
   - 真正打分时必须先做**截面标准化**。

**截面 z-score** 是什么：

```python
# 同一天、所有股票放在一起，减均值除标准差
z = (x - x.mean()) / x.std(ddof=0)
z[x.std(ddof=0) == 0] = 0.0     # 只有一只股票或全部相同 → 视为中性
```

这样每只股票的因子值变成"在今天的横截面里排第几档"，跨股票可比。`PVCF = z(PCF) + z(VCF)` 就是把"价格收敛"和"成交量收敛"两个维度加在一起。

### 2.4.3 打分与"算式化"的规则

7 个策略里最简单的是线性加权 + 规则扣分：

```python
score = composite_score(trend_score, fund_score, weights=(0.6, 0.4, 0.0))
if 收盘价/ma20 - 1 > 0.10:  score -= 100   # 追高，直接否掉
if 收盘价/ma20 - 1 > 0.05:  score -= 30    # 偏离过大
if ma20 < ma60:             score -= 100   # 中期趋势向下
```

新增的因子就插在"加权和"后面：

```python
if conv_weight:                              # 默认 0 → 这段根本不执行
    score += conv_weight * zscore(df, "conv_pcf")
```

**为什么默认 0 很重要**：它让"加了一个新因子"这件事在数值上等于"没加"。所以 7 个策略能逐值回归，一旦有人手滑把权重写成 0.1，回归立刻报错。

### 2.4.4 分年度指标与换手率怎么算

`calc_metrics` 只给全区间结果，熊市和牛市会被平均掉，所以补了两个函数：

```python
def calc_annual_metrics(equity, trades):
    for year, eq in equity.groupby(equity.index.year):
        # 交易按"平仓日期"归年：跨年持仓算在卖出那一年
        trades_year = trades[trades["exit_date"].dt.year == year]
        out[str(year)] = calc_metrics(eq, trades_year)

def calc_turnover(equity, trades):
    avg_equity  = equity.mean()                                   # 平均总资产
    buy_amount  = (trades["entry_price"] * trades["shares"]).sum()
    single_side = buy_amount / avg_equity                         # 单边换手（倍）
    return {"single_side": single_side, "annual": {...按年拆分...}}
```

换手率的意义：单边年换手 16 倍 ≈ 一年把本金彻底"翻仓"16 次。按 A 股实际费率（佣金 0.03% 双边、卖出印花税 0.1%、假设滑点 0.1%）粗算，年成本 ≈ `16 × (0.03% + 0.1% + 0.1%) ≈ 5.8%`。这就是为什么"择股不错但收益为负"——**成本把人磨死了**。

### 2.4.5 A/B 实验怎么保证公平

`scripts/measure_factor_ab.py` 的四个设计点：

1. **同一份数据**：每个 arm 都重新 `Storage().load_market_maps(...)`，用同一 `max_codes` 抽样逻辑（`codes[::step]`），保证股票池相同。
2. **同一套参数**：只有被测参数不同（如 `conv_weight`），其余全用 `BacktestConfig` 默认值。
3. **子进程隔离**：父进程只发 spec、收 `RESULT {json}` 一行；避免同进程复用 pandas/模块级缓存导致"第二次跑出第一次的结果"。
4. **可复现**：同一配置跑两遍，`metrics/annual/turnover/benchmark_return` 必须逐字符相同（做过 3 个 arm 的 `DETERMINISM PASS` 自检）。

报告同时给：总表（收益/年化/回撤/夏普/换手/笔数/胜率/基准）+ 每个 arm 的分年度表。**只看年化是不够的**——有可能"年化一样但回撤差了 10 个点"，那也不算改进。

### 2.4.6 RRG 的数学与代码对应

RRG 想回答的问题是："哪些行业正在变强、哪些正在变弱。"

```python
# 1) 行业指数：成分股日收益的等权平均，再链式累乘成指数
daily_ret = 个股收益在 (date, industry) 上取平均          # 等权
index     = (1 + daily_ret.fillna(0)).groupby(industry).cumprod()

# 2) 相对强度：行业指数 / 基准（31 行业等权） × 100
rs = index / benchmark * 100

# 3) RS-Ratio：相对强度相对 220 天前的位置，取 20 日均线（平滑）
rs_ratio = (100 * rs / rs.shift(220)).rolling(20).mean()

# 4) RS-Momentum：RS-Ratio 自身的变化率，再平滑
rs_mom = (100 * rs_ratio / rs_ratio.shift(60)).rolling(20).mean()

# 5) 四象限：(100,100) 为中枢
#    ratio>100 & mom>100 → 领先；ratio>100 & mom<100 → 转弱
#    ratio<100 & mom<100 → 落后；ratio<100 & mom>100 → 转强
```

**两个必须注意的实现细节**：

- **预热**：第 4 步需要 `220 + 20 - 1 = 239` 行，第 5 步还需要再 60+20 行 → 完整 RRG 需要 **318 行**。不足时直接抛 `ValueError` 并说明"需要 318 行、实际 N 行"，**不能静默**。
- **防未来函数**：调仓日 d 只能使用 d **之前**已成形的最新 RRG 值（代码里用"严格小于 d 的最后一天"），否则等于用当天收盘价决定当天开盘的仓位。

选行业（A 方案）：只在"转强"象限里挑，按 `((ratio−100)² + (momentum−100)²)` 开方后降序，取前 6。

### 2.4.7 行业轮动回测：成本与"权重自己会漂"

```python
for day in days:
    if 到调仓日:
        目标权重 = 1/6 分给 6 个选中行业，其他为 0
        换手 = 0.5 * Σ|目标权重 - 当前权重|      # 单边换手
        成本 = 换手 * 2 * 0.0010                  # 双边 × 10bp
    # 不调仓的日子：权重随行业指数涨跌自然漂移
    当前权重 = 当前权重 * (1 + 当日行业收益)
    当前权重 /= 当前权重.sum()
```

成本口径必须写死并在报告里披露（这里单边 10bp、双边 20bp），否则"轮动看起来有效"很容易是成本假设太乐观。基准用"31 个行业等权"，这样比较的是"轮动选行业" vs "全行业躺平"，而不是 vs 沪深 300（后者会混入大小盘风格差异）。

### 2.4.8 两段式配置：白名单 + 哨兵值 + 降级

**旧代码的病根**（`strategy/custom.py`）：

```python
if "ma20" in df_factors.columns:      # 列不存在 → 整条规则静默跳过
    ...
```

问题：LLM 生成一个 `dev_ma = 60` 的配置，但因子表里没有 `ma60` 列时，规则直接消失，用户看到的是"策略跑出来了"，但实际少算了一条。

**新做法三层**：

```python
# 第一层：类型默认值（趋势跟随 → ma10/ma30、权重 0.6/0.4 …）
# 第二层：全局默认值（atr_m_exit=3.0、hold_days=30 …）
# 第三层：缺字段 → 该规则禁用 + 记录 degraded
config, issues, degraded = normalize_config_typed(raw, archetype_key,
                                                  available_columns=today_columns)
# degraded = [{"rule": "dev_ma", "missing": "ma60",
#              "message": "缺 ma60 列，已禁用「偏离均线」规则"}]
```

哨兵值（sentinel）是"用特殊值表示禁用"的老约定，继续复用：

| 字段 | 禁用值 | 含义 |
|---|---|---|
| `dev_ma` | 0 | 不计算偏离 |
| `mom_min` | −100 | 不启用动量下限 |
| `liquidity_min` | 0 | 不做流动性过滤 |
| `mv_pct` | 0 | 不做小市值分位过滤 |

这些值必须写进文档与 `PARAM_DESC`，否则"0 到底是不启用还是真的设 0"会成为长期维护陷阱。

### 2.4.9 股本与披露日：公式与防未来函数

**流通市值/股本的反推**（日线里没有股本字段，但有成交额和换手率）：

```
流通市值 = 成交额 ÷ 换手率          # 换手率 = 成交量 / 流通股本
流通股本 = 流通市值 ÷ 收盘价
```

实测与快照交叉验证：`000001` 反推 2198.9 亿 vs 快照 2194.8 亿（−0.19%）；`600519` 16710.7 vs 16635.5（−0.45%）；`300750` 9832.2 vs 9762.8（−0.71%）；`002594` 2884.5 vs 2885.2（+0.03%）。

**总股本**没有历史来源，只能两段式：
- 当天快照：`总股本 = 总市值 ÷ 最新价`（来自东财快照接口）；
- 历史：`历史总股本 ≈ 当时流通股本 × (今天总股本 ÷ 今天流通股本)`，标 `source="proxy"`。

这个 proxy 在定增/回购/解禁后会失真，所以只用于"市值分档"（比如"最小 20%"），不用于精确市值。

**披露日防未来函数**：

```python
def as_of_disclosure(code, date):
    # 只返回公告日 <= 查询日的记录
    rows = [r for r in db[code] if r.announce_date <= date]
    return rows[-1] if rows else 法定截止日(最近报告期)+兜底标记
```

缺失时用法定截止日（年报/一季报 4-30、半年报 8-31、三季报 10-31）——它一定**不早于**真实公告日，所以不会偷看未来，代价是"迟到一点"。

## 2.5 结论表（给专业读者的收尾）

| 任务 | 实现 | 判定 | 默认状态 |
|---|---|---|---|
| A 收敛因子 | 5 列 + `conv_weight` | 趋势全档变差；突破无一档满足判定线 | 关闭（可选参数） |

**限制与未做**：
- 行业分类只有 2026-10 一个快照，历史无法回补 → RRG 存在前视风险（已在报告披露）。
- 历史总股本为比例外推，不可用于精确市值。
- `data/processed/market/` 只有 2 天快照 → 事件驱动、打板类本轮不做。
- A/B 用 800 只抽样，统计功效有限；结论"不成立"比"成立"更稳健（不成立不依赖大样本精度）。

**下一步建议（按性价比排序）**：
1. 降低换手：把日频调仓改为 N 日调仓/信号缓冲（已有 `rebalance_freq`），先量化成本曲线。
2. 熊市择时：启用现成的 `factors/regime.py` + `BacktestConfig.market_timing`，重点看 2022、2026 两段。
3. 之后才是"再找因子"。
